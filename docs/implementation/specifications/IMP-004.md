# IMP-004 – Core Contracts Implementation Specification

## 1. Objective

Implement the Core Contracts module as defined in ADR-008.

This module provides the standardized interfaces for engines and data providers, enabling the Orchestrator to coordinate execution without coupling to specific implementations.

## 2. Scope

### Included

- `IEngine<TRequest, TData>` interface.
- `IDataProvider<TParams, TData>` interface.
- Barrel file for unified imports.
- Immutable by design.
- Documentation for all exported types.

### Not Included

- Business logic.
- Validation logic.
- Engine implementation.
- Provider implementation.
- Orchestrator implementation.
- Core Types modifications.
- core/results modifications.

## 3. Required Files

| File Path | Purpose |
|-----------|---------|
| `core/contracts/engine.contract.ts` | Defines `IEngine<TRequest, TData>`. |
| `core/contracts/provider.contract.ts` | Defines `IDataProvider<TParams, TData>`. |
| `core/contracts/index.ts` | Barrel file for all Core Contracts exports. |

## 4. Files Explicitly Out of Scope

- `core/types/**/*` (Frozen)
- `core/results/**/*` (Frozen)
- `engines/**/*`
- `platform/**/*`
- `docs/**/*`

## 5. IEngine Contract

```typescript
interface IEngine<TRequest, TData> {
  execute(request: TRequest): Promise<Result<TData>>;
}
TRequest – The type of the request accepted by the engine.

TData – The type of the data returned in the Result object.

Returns Promise<Result<TData>> where Result is from core/results.

6. IDataProvider Contract
typescript
interface IDataProvider<TParams, TData> {
  fetch(params: TParams): Promise<TData>;
  validate(credentials: unknown): Promise<boolean>;
  transform(raw: unknown): TData;
}
TParams – The type of parameters required for the data fetch.

TData – The type of data returned by the provider.

validate – Authenticates with the data source.

transform – Converts raw data to canonical domain objects.

7. Generic Parameter Strategy
Both contracts use explicit generic parameters:

IEngine: TRequest and TData ensure type-safe request and response handling.

IDataProvider: TParams and TData ensure type-safe fetch parameters and data retrieval.

This approach:

Preserves type safety across implementations.

Eliminates casting in engine and provider code.

Supports diverse engine and provider implementations.

8. Result<TData> Usage
IEngine.execute() must return Promise<Result<TData>>.

Result is imported from core/results.

The data field of Result is typed as TData.

## Unresolved Implementation Decisions

1. **`validate` method parameter type**: ADR-008 and ARCHITECTURE.md §7.1 specify `validate(credentials)`, but the exact type is not defined. Using `unknown` is the safest generic approach, as credentials may vary by provider.

2. **`transform` method return type**: The return type `TData` is generic, but the method may need to handle errors during transformation. This is an implementation concern that providers will handle internally.

3. **Interface naming convention**: The existing Core Types interfaces do not use the `I` prefix (e.g., `Property`, `Location`). For consistency, `IEngine` and `IDataProvider` may be preferred to distinguish behavior contracts from data contracts, or the prefix may be omitted for consistency. This is a convention decision.

4. **Export strategy**: Should `core/contracts/index.ts` re-export all types explicitly or use wildcard exports? This is a convention decision.
